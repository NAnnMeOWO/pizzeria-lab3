# Лабораторная работа №3 — Пиццерия (SQLModel)

**Вариант:** Пиццерия.
**СУБД:** SQLite 3 (файл `pizzeria.db`).
**ORM:** SQLModel 0.0.48.
**Python:** 3.10+.

## О проекте

Проект реализует информационную систему пиццерии на основе предметной области из ЛР1 и схемы БД из ЛР2. Схема приведена к 3НФ и включает 15 таблиц, покрывающих все бизнес-процессы: приём заказа, приготовление, доставку, оплату, складской учёт, работу с персоналом и отчётность.

## Структура проекта

| Файл | Назначение |
|---|---|
| `database.py` | Подключение к SQLite + `create_db_and_tables()` |
| `models.py` | 15 моделей-таблиц (SQLModel) |
| `seed.py` | Наполнение БД тестовыми данными |
| `requests.py` | 12 функций-выборок под бизнес-процессы |
| `pizzeria.db` | Файл БД с данными (SQLite) |
| `pizzeria_dump.sql` | Дамп БД (SQL-команды для восстановления) |
| `requirements.txt` | Зависимости проекта |
| `README.md` | Этот файл |

## Модели (15 таблиц)

**Справочники и меню:** Client, Employee, Courier, Shift, MenuCategory, Dish.

**Склад и рецептуры:** Ingredient, Recipe (M:N «Блюдо ↔ Ингредиент»).

**Заказы и оплата:** Order, OrderItem, PaymentSystem, Payment.

**Поставки:** Supplier, Supply, SupplyLine.

Основные связи:
- Клиент 1:M Заказ
- Заказ 1:M Позиция заказа
- Блюдо 1:M Позиция заказа
- Блюдо M:N Ингредиент (через Recipe)
- Сотрудник 1:M Заказ, Сотрудник 1:M Смена
- Курьер 1:1 Сотрудник, Курьер 1:M Заказ
- Заказ 1:1 Оплата
- Поставщик 1:M Поставка, Поставка 1:M Строка поставки

## Запросы (requests.py)

Реализованы выборки под основные процессы.

**Заказы:**
- get_order_with_items(order_id) — детали заказа (клиент, позиции, блюда, оплата)
- get_orders_by_status(status) — заказы по статусу
- get_orders_for_period(start, end) — заказы за период

**Склад и рецептуры:**
- get_recipe_for_dish(dish_id) — состав блюда
- get_low_stock(threshold) — ингредиенты с остатком ниже порога
- calculate_ingredients_needed(dish_id, portions) — расчёт расхода на N порций

**Отчётность:**
- revenue_for_period(start, end) — выручка за период
- top_dishes(limit) — топ блюд по продажам
- orders_count_by_type() — количество заказов по типам
- courier_deliveries() — количество доставок у каждого курьера

**Поставки:**
- supplies_for_period(start, end) — поставки за период
- supply_details(supply_id) — детализация поставки по ингредиентам

## Как запустить

1) Установить зависимости:

pip install -r requirements.txt

2) Создать БД и наполнить данными:

python seed.py

Ожидаемо: Seed data inserted.

3) Запустить демонстрацию всех запросов:

python requests.py

Ожидаемо: 12 блоков === 1. ... === … === 12. ... === с данными.

## Как восстановить БД из дампа

Если файл pizzeria.db утерян, его можно восстановить из дампа:

python -c "import sqlite3; con = sqlite3.connect('pizzeria.db'); con.executescript(open('pizzeria_dump.sql', encoding='utf-8').read()); con.close(); print('restored')"

Ожидаемо: restored. После этого в БД будут все таблицы и данные.

Проверка:

python -c "import sqlite3; con = sqlite3.connect('pizzeria.db'); print('clients:', con.execute('SELECT COUNT(*) FROM client').fetchone()[0]); print('orders:', con.execute('SELECT COUNT(*) FROM \"order\"').fetchone()[0]); con.close()"

Ожидаемо:

clients: 2
orders: 2

## Примечания

- Все поля datetime в seed.py передаются с tzinfo=timezone.utc — требование SQLModel 0.0.48.
- Поля datetime в моделях — «наивные» datetime (SQLModel 0.0.48 не поддерживает NaiveDatetime).
- Таблица order — зарезервированное слово SQL; SQLAlchemy автоматически экранирует имя.
- echo=True в database.py печатает SQL-лог в консоль — удобно для отладки.
